Site exclusions

Open Site Exclusions tab and enter one URL pattern per line. Exclusions take priority over every matching fill, click, and script rule. Clipboard values are not read for excluded rules.

  • https://example.com/* excludes every path on that host.
  • https://*.example.com/* excludes its subdomains. Add both patterns to exclude the main host and its subdomains.
  • https://example.com/private/* excludes only that path.

Site exclusions and rule Site Pattern share the same matching logic. The scheme is optional: example.com matches only the root page on any supported scheme, while https://example.com matches only its HTTPS root. Use example.com/* to match all paths. A path without a wildcard matches only that exact URL, including its query and fragment.

* matches any characters. Matching uses the same URL patterns as the rule’s Site field, rather than page titles or regular expressions. Blank lines are ignored.

Each iframe is checked against its own URL. If a page embeds a form from another host, add a pattern for that host too. Save settings, then reload the page. Removing an exclusion does not undo previous page changes.

Full JSON backups

Export JSON or Copy to Clipboard backs up rules, variables and their priority and active states, site exclusions, and all General preferences, including unsaved editor changes.

Open Import JSON, paste a backup or drop one JSON file, then click Import JSON. This restores the complete saved configuration and reloads settings. Invalid files change nothing. CSV and old rules-only formats are no longer supported.

The versioned format validates all fields and numeric ranges before saving. Loop intervals must be whole seconds from 3 to 2147483; loop counts range from 0 to 2147483647 (0 means unlimited). Backups include actual private rule values, but exclude capture buffers.

Download a full JSON example. Its rule targets the published Practice page; importing it also restores its example preferences.

Dynamic values and escaping

Enter these expressions in a rule’s Value field. You can combine them with ordinary text, such as Order-{{alnum:12}}. Script rules are not expanded.

  • {{today}}: local date in YYYY-MM-DD format.
  • {{random:6}}: random digits, including possible leading zeros.
  • {{random:1-100}}: inclusive random integer range. Ordered bounds must fit between −2147483648 and 2147483647.
  • {{alnum:12}}, {{lower:8}}, {{upper:8}}, {{hex:6}}: letters and digits, lowercase letters, uppercase letters, or lowercase hexadecimal characters.
  • {{choice:red|green|blue}}: choose one nonempty option. Use \| for a literal pipe inside an option and \\ for a literal backslash. Spaces are preserved.
  • {{uuid}}: random UUID.
  • {{clipboard}}: clipboard text, inserted literally without expanding expressions inside it.

String lengths default to 6 and are limited to 1–64 characters. Each value resolves once per rule per frame and stays stable during rechecks. Reloading resolves it again; separate frames may receive different random values.

Prefix an expression with one backslash: \{{today}} fills the literal text {{today}}. Two backslashes before an expression output one backslash and allow expansion. Other backslashes remain unchanged. This follows Handlebars inline escaping; full helpers, raw blocks, and nested expressions are not supported. Unknown expressions, invalid ranges, and empty choice options remain unchanged.

Manual execution

  1. Save your rules. Open General Settings, enable Manual execution, and save settings.
  2. Reload the form page. Nothing fills automatically.
  3. Right-click the page and choose Execute rules, or press Ctrl+Shift+K on Windows/Linux or ⌘+Shift+K on macOS. Chrome shortcut settings can customize this binding; the menu displays the assigned shortcut.

The extension icon shows RUN when execution starts, OFF when the top page is excluded, or ERR when the command is unavailable. RUN means started; review page results to confirm successful filling.

Each invocation reads saved rules and settings, then runs matching rules once across the page’s frames. Exclusions still apply. Loop mode is not started, even if its preference is enabled. Newly appearing fields on the same route remain eligible until navigation. After navigating, trigger another manual run.

Unsaved editor changes are not used. Chrome internal pages and other protected pages cannot be filled. Review click and script rules before running, because they can submit forms.

Try it on the Practice page: save a text rule, turn on manual mode, reload, and trigger the command.

Named variables

In Rules, the green power button means active and the grey crossed power button means inactive. Click once to change state, then save rules.

Open Variables, add a name such as email and a fictional value such as alex@example.test, then save. Use {{var:email}} in any matching rule. Names begin with a letter or underscore and contain letters, numbers, underscores, or hyphens. Names are case sensitive.

Variables may reference other variables: a greeting value of Hello {{var:name}} reuses name. Missing or inactive names, cycles, and nesting beyond 32 references stop the affected rule and report an error. Script rules are not expanded.

Use \{{var:email}} to fill the reference literally. Dynamic values inside variables resolve once per frame and are shared by rules using that variable. Rechecks reuse the result; a reload or manual run resolves fresh values. Clipboard contents are inserted literally. Separate frames may receive different random values.

Variable values stay local and visible in settings. Use the green/grey power button to activate or deactivate a variable, and the trash button to delete it. Save settings to apply changes. Variables are intended for reusable form text, not passwords.
